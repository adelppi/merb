# D-0007 出題の画面の操作と、出す問題

- 日付: 2026-11-03
- 決めた人: adelppi
- 関係する Issue と PR: #17
- 解決した未解決の項目: OQ-009
- 置き換える記録: なし

## 背景

1問を解く出題の画面を作るにあたり、画面の URL、札を運ぶ操作、答え合わせのきっかけ、結果として出すものを決める必要があった。分類を選ぶ画面はまだなく、`content/questions/` に問題の JSON もまだない。

## 決定

- 出題の画面の URL は `/quiz` にし、トップページにリンクを置く。
- 札置き場の札をタップすると、回答エリアの末尾へ運ぶ。回答エリアの札をタップすると、札置き場の元の位置へ戻す。
- ドラッグでは、札置き場の札を回答エリアの好きな位置へ入れられ、回答エリアの中で並べ替えられ、札置き場へ戻せる。札置き場の中では並べ替えない。戻した札は元の位置に戻る。
- 答え合わせは、「答え合わせ」のボタンを押したときにする。回答エリアに札が1枚もなくても押せる。
- 正解したときは、「正解」と、並べたもの以外の読み方と、「次の問題」のボタンを出す。
- 間違えたときに「もう一度解く」を押すと、回答エリアの札を並べたまま解き直せる。
- 「答えを見る」を押すと、すべての読み方を `answers` の順に見せる。
- 分類を選ぶ画面ができるまでは、すべての問題からランダムに出し、「次の問題」で続ける。問題が2問以上あれば、直前と同じ問題は出さない。
- テスト用の問題は `e2e/fixtures/questions/` に置き、Playwright のビルドだけが環境変数 `MERB_QUESTIONS_DIR` でそちらを読む。本番は `content/questions/` を読み、問題がなければ「問題がありません」と出す。

詳しい振る舞いは [1問を解く出題の画面](../specs/quiz.md) に書いた。

## ほかの選択肢

- トップページを開くとすぐに問題が出る案。採らなかった。
- 札を並べ終えたら自動で答え合わせをする案。採らなかった。
- 札が1枚もないときは答え合わせのボタンを押せなくする案。わからない問題でもすぐに答えを確かめられるよう、押せるようにした。
- 「もう一度解く」で札をすべて札置き場に戻し、混ぜ直す案。採らなかった。
- 答えを見せるとき、先頭の読み方だけを見せる案。採らなかった。
- 正解したとき、「正解」だけを出す案と、少し待って自動で次の問題へ移る案。採らなかった。
- 分類を選ぶ画面ができるまで、1問だけを出す案。採らなかった。
- 回答エリアの札をタップで戻すとき、札置き場の末尾に並べる案。採らなかった。
- ドラッグは回答エリアの中の並べ替えだけにし、札置き場と回答エリアの間はタップで運ぶ案。採らなかった。
- `content/questions/` に確かめた問題を数問入れ、本番とテストの両方で使う案。Issue #17 の範囲外の「問題の JSON の中身を作ること」に当たるので採らなかった。

## 根拠

- `/quiz` に分けておくと、設定画面と同じ作りになり、あとで分類を選ぶ画面を足しやすい。
- 判定では余った札があってもよい（[D-0004](D-0004-question-format.md)）ので、アプリは利用者が並べ終えたかを知れない。そのため、答え合わせはボタンでする。
- 「もう一度解く」で札を残すと、スマートフォンで並べ直す手間が少ない。
- テスト用の問題を別のフォルダに置くと、確かめていない問題を本番に出さずに、画面を Playwright で確かめられる（[D-0002](D-0002-question-source.md)）。
