# D-0006 言語は URL に含めず、ローカルストレージに保存する

- 日付: 2026-11-03
- 決めた人: adelppi
- 関係する Issue と PR: #15
- 解決した未解決の項目: OQ-008
- 置き換える記録: D-0003 のうち「URL で言語を分ける（`/ja`、`/en`）」の点。D-0005 のディレクトリの構成のうち `src/app/[locale]/` の点

## 背景

画面の文言を日本語と英語で切り替えられるようにするにあたり、言語の決め方と、利用者が言語を選ぶ手段を決める必要があった。D-0003 では、next-intl を使い、URL で言語を分ける（`/ja`、`/en`）と決めていた。

## 決定

- 言語は URL に含めない。URL は言語によらず同じにする。
- 言語を保存していないときは、日本語で出す。
- 設定画面を作り、そこで日本語か英語を選べるようにする。選んだ言語は、ブラウザーのローカルストレージに保存する。
- どの画面にも置く言語の切り替えのリンクは作らない。言語は設定画面だけで切り替える。
- ページはビルドのときに日本語の文言で静的に作る。ブラウザーでローカルストレージを読み、英語が保存してあれば英語の文言に差し替える。英語に差し替わるまでは本文を見せない。
- next-intl は、URL で言語を分ける機能を使わず、文言を出す部分だけを Client Component で使う。
- 文言のファイルは `src/i18n/messages/` に置く。
- ページは、D-0005 の `src/app/[locale]/` ではなく、`src/app/` に直接置く。

## ほかの選択肢

- D-0003 のとおり、URL で言語を分ける案。共有したリンクを、送った人と同じ言語で開けて、検索エンジンにも言語ごとに載る。merb ではブラウザーを頻繁に変えないので、URL を言語によらず同じにするほうを選んだ。
- URL で言語を分け、`/` を開いたときだけ、ローカルストレージに保存した言語へ移す案。上と同じ理由で採らなかった。
- サーバーで cookie を読んで、その言語でページを描く案。リクエストごとにサーバーでページを描くことになり、D-0003 の「ページはビルドのときに静的に作る」と、D-0005 の「サーバーで処理することがない」と食い違うので採らなかった。
- どの画面にも、もう一方の言語へのリンクを置く案。置かないことにした。

## 根拠

- ローカルストレージはブラウザーごとに値を持つので、アカウントもサーバーも使わずに言語の設定を残せる。言語の設定は学習の記録ではないので、`vision.md` の「やらないこと」にある学習の記録の保存には当たらない。
- ブラウザーで文言を差し替えると、ページを静的に作ったまま、サーバーの処理を持たずに済む。
- 英語を保存した人に、開いた直後の日本語が見えないよう、差し替わるまで本文を隠す。日本語の人には、この待ちは起きない。
- 両方の言語の文言をブラウザーに送ることになるが、merb の文言は少ない。

## 影響

- `docs/specs/i18n.md` を新しく書いた。
- `AGENTS.md` の「ソースコードの置き場」から `src/app/[locale]/` を外し、`src/i18n/` に文言のファイルを置くことを書いた。
- D-0003 と D-0005 の末尾に、この記録で一部を置き換えたことを1行足した。
- `open-questions.md` に OQ-008 を起票し、解決済みにした。
