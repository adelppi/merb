## 背景

ソースコードを書き始めるために、言語、フレームワーク、実行環境と、`vision.md` の「やること」を作るのに使うライブラリを決める必要があった。開発者の希望は、Next.js と Vercel だけで完結させ、認証も DB も持たないこと。問題はリポジトリの JSON として持ち、アプリでは LLM を呼ばない（[D-0002](D-0002-question-source.md)）。

## 決定

| 用途 | 使うもの |
|---|---|
| 言語 | TypeScript |
| フレームワーク | Next.js の App Router |
| 実行環境 | Vercel。ページはビルドのときに静的に作る |
| パッケージマネージャー | pnpm |
| 数式の描画 | KaTeX |
| 札のドラッグと並べ替え | dnd-kit（`@dnd-kit/core` と `@dnd-kit/sortable`） |
| 画面の文言の日本語と英語の切り替え | next-intl。URL で言語を分ける（`/ja`、`/en`） |
| 問題の JSON の形の検査 | Zod |
| lint と整形 | Biome |
| 単体テスト | Vitest |
| ブラウザでの操作のテスト | Playwright |

問題の JSON は、次の3つを Vitest のテストとして検査する。

- JSON の形が、Zod で書いた形に合っているか。
- 数式を KaTeX で描けるか。
- 正解の読み方を、その問題の札で組み立てられるか。

## ほかの選択肢

- パッケージマネージャーに npm か Bun を使う案。pnpm を選んだ。
- 札のドラッグに Pragmatic drag and drop を使う案。並べ替えの見た目を自分で組む部分が多いので採らなかった。
- 札のドラッグに Motion の Reorder を使う案。札置き場と回答エリアの間の移動を自分で組む必要があるので採らなかった。
- 文言の切り替えに、ライブラリを使わず言語ごとの文言の表を TypeScript で持つ案。next-intl を選んだ。
- lint と整形に ESLint と Prettier を使う案。Biome を選んだ。
- ブラウザでの操作のテストを今は入れない案。Playwright を入れることにした。

## 根拠

- 問題はリポジトリの JSON から出し、サーバーで処理することがないので、ページを静的に作れる。
- dnd-kit は、タッチとキーボードでの操作に対応し、並べ替えの部品を持つ。`vision.md` の「スマートフォンでも使える」に合う。
- 問題の JSON の検査をテストに入れると、読み方の誤りや描けない数式を出題の前に見つけられる。`vision.md` の判断の基準の1つ目「出す問題の読み方が正しいこと」に合う。
