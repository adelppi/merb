# D-0011 問題ごとに日本語と英語の問題文を持ち、出題の画面に出す

- 日付: 2026-11-03
- 決めた人: adelppi
- 関係する Issue と PR: #24
- 解決した未解決の項目: OQ-013
- 置き換える記録: なし

## 背景

出題の画面には数式と札だけが出ていて、何をすればよいかが伝わりにくかった。問題文を出すと、`vision.md` の「判断の基準」の2つめ（説明文は入れない）とぶつかる。開発者は、問題文をこの基準の例外とし、`vision.md` を書き換えることに合意した。

開発者が決めたことは次のとおり。

- 問題文は、問題ごとに問題の JSON に持つ。
- 日本語と英語の両方を、すべての問題に必ず書く。
- 出題の画面では、選んでいる言語のほうの問題文を、数式の上に出す。

キーの名前、128 問の問題文の書き方、文面は、推奨案で決め、開発者が PR で確かめることにした。

## 決定

- `vision.md` の「判断の基準」の2つめに、出題の画面には何をすればよいかを伝える問題文を例外として出すことを書き足す。
- 問題の JSON の各問題に、`prompt` を必須のキーとして足す。`prompt` は、日本語の問題文の `ja` と、英語の問題文の `en` を持つ。キーの名前は、画面の文言の言語のコード（`ja`、`en`）とそろえる。
- 問題文は、何をすればよいかを伝える、飾りのない短い1文にする。答えの読み方やその一部は書かない。
- いまの 128 問とテスト用の問題は、すべて同じ次の文にする。
  - `ja`: 次の数式を英語で読んでください。
  - `en`: Read the expression in English.
- 問題の JSON の検査では、`ja` と `en` があり、どちらも空白だけの文字列でないことを確かめる。文面が上の文と同じかどうかは検査しない。
- 問題を作るプロンプト（`content/prompt.md`）では、上の文をそのまま使うよう頼む。

詳しい形は [問題の JSON の形](../specs/question-format.md)、出し方は [1問を解く出題の画面](../specs/quiz.md) に書いた。

## ほかの選択肢

- `promptJa` と `promptEn` を問題に直に置く案。言語が増えたときにキーが増え、言語のコードと対応させにくいので採らなかった。
- 問題文を観点に合わせて変える案（例: 小数の問題で「小数を英語で読んでください。」）。観点ごとの言い分けは読み方の手がかりになりやすく、128 問を2つの言語で確かめる量も増えるので採らなかった。
- 問題文を分類ごとに変える案。分類が違っても、どの問題でもすることは同じなので採らなかった。
- 札を並べることまで書く案（例: 「札を並べて、次の数式の英語での読み方を作ってください。」）。札を運ぶ操作は画面から分かり、文が長くなるので採らなかった。
- 問題文を問題の JSON に持たず、画面の文言のファイルに1つだけ置く案。開発者が、問題ごとに持つと決めたので採らなかった。
- 検査で、すべての問題文が同じ文であることを確かめる案。問題ごとに持つ形にした意味がなくなるので採らなかった。

## 根拠

- Issue #24 に例として書かれた文を使った。
- `vision.md` の「判断の基準」の2つめ（画面がシンプルであること）に沿い、例外として出す問題文も、短く飾りのない1文にとどめた。
- 問題ごとに持つ形にしておくと、あとで一部の問題だけ文を変えたくなったときに、形を変えずに書き換えられる。
