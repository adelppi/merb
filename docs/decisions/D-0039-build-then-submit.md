# D-0039 ストア版はビルドと提出を分けて実行する

- 日付: 2026-11-08
- 決めた人: adelppi（Issue #103 の依頼）。どちらを標準にするかは Claude Code が決めた。adelppi が PR で確かめる
- 関係する Issue と PR: #103
- 解決した未解決の項目: なし
- 置き換える記録: D-0031 のうち、手順書でビルドと提出を `--auto-submit` で続けて行う点

## 背景

`docs/release.md` には `eas build --auto-submit` でビルドと提出を続けて行うと書いていた。1.0.0 では、`eas build` と `eas submit` を分けて実行した。どちらを標準にするかを決める必要があった。

## 決定

- ストア版は、`eas build` でビルドし、成功を確かめてから `eas submit` で App Store Connect に送る。
- 審査用のメモは `docs/store-listing.md` の文面を使い、実機の画面収録を添える。
- OTA を配信する前に、`eas fingerprint:compare` で、配信先のストア版のビルドと fingerprint が一致することを確かめる。

## ほかの選択肢

- `--auto-submit` で続けて行う案。1回の実行で済むが、ビルドの結果を見る前に提出が始まる。1.0.0 で実際に行った手順と違うので採らなかった。

## 根拠

- 1.0.0 では、最初の `eas build` が認証情報の不足で止まり、対話で作り直した。ビルドと提出を分けると、どちらで止まったかが分かりやすい。
- 1.0.0 の最初の審査は Guideline 2.1 で、実機の画面収録と、目的、使い方、外部サービス、地域差、規制の説明を求められた。メモと収録を添えて再提出し、審査に通った。
- 最初の OTA の前に fingerprint を比べ、一致を確かめてから配信した。公開版のアプリに届いたことを adelppi が確かめた。

## 影響

- `docs/release.md` と `AGENTS.md` を書き換えた。
