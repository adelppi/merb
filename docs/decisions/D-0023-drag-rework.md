# D-0023 札のドラッグは自前で組み直し、動かし始めの判定を長押しから移動量に変える

- 日付: 2026-11-03
- 決めた人: adelppi が不具合と欲しい動きを伝え、AI が組み方を選んだ。PR で adelppi が確かめる
- 関係する Issue と PR: #54
- 解決した未解決の項目: なし
- 置き換える記録: [D-0016](D-0016-math-and-drag-libs.md) のうち、ドラッグを 250 ミリ秒の長押しのあとに始める点。[D-0022](D-0022-drag-with-gesture-handler-v3.md) のうち、動かない原因の見立てと、出題の画面のスクロールを Gesture Handler の `ScrollView` にする点

## 背景

[D-0022](D-0022-drag-with-gesture-handler-v3.md) のあとも、札を長押ししてドラッグできなかった。adelppi からは、札を持ち上げたときに落ちる位置が見えないこと、落ちる位置の札が避けないことも伝えられた。出題の画面をスクロールさせないことも頼まれた。

## 決定

- ドラッグを動かせなくしていた原因は、ドラッグ中に札や札置き場の `zIndex` を切り替えていたこと。`zIndex` を変えると、親の中で View の並びが入れ替わり、そのたびにジェスチャーが取り消される。シミュレーター（iOS 26.5）で、`zIndex` を外すとドラッグが最後まで続くことを確かめた。
- 持ち上げた札は、元の View を動かさず、見えなくする。指に付いて動く見た目は、盤面の最後に置いた別の View（Ghost）が出す。後ろの View ほど手前に描かれるので、`zIndex` は使わない。
- ドラッグ中は、札の View の並びを変えない。落ちる位置の空きは、各札の前に置いた枠（Slot）の幅を広げて作る。ほかの札は、Reanimated の `LinearTransition` で動く。
- 入れる位置は、指に対する札の並びで決める。上の行の札と、同じ行で中心が指より左にある札の数を、入れる位置の番号にする。これまでの「札の上に落とすとその札の前」は、札の右半分に落としても前に入った。
- ドラッグは、指を 6 ポイント動かしたときに始める。長押しの待ち時間はなくす。
- 出題の画面は、スクロールしない。`ScrollView` をやめ、ふつうの `View` にする。
- ライブラリは足さない。Gesture Handler 3 と Reanimated の組み合わせは変えない。

## ほかの選択肢

- `react-native-sortables`。並べ替えのアニメーションと落とす位置の表示を持つが、確かめた範囲では、1つの並べ替えの中での移動が対象で、札置き場から回答エリアへの移動を扱う例は見つからなかった。採らなかった。
- `react-native-reanimated-dnd`。`Draggable`、`Droppable`、`Sortable` を持つが、確かめた範囲では、札置き場から回答エリアへ移しながら、回答エリアの札が避ける動きの例は見つからなかった。採らなかった。
- 長押しでドラッグを始める作りを続ける案。長押しは、スクロールとの取り合いを避けるために置いたものだった。スクロールをやめたので、待ち時間を置く理由がなくなった。

## 根拠

- 原因の確認は、シミュレーターの Expo Go で、Maestro の `swipe` を使った。`zIndex` を切り替えているときは、動かし始めた直後にジェスチャーが取り消され、外すと最後まで続いた。
- 長押しの待ち時間をなくしたことで、Maestro の `swipe` でもドラッグが送れるようになった（[D-0021](D-0021-operation-test-tool.md) では送れなかった）。
