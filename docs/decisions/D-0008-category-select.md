# D-0008 出題の範囲を分類から選ぶ画面と、選んだ分類の渡し方

- 日付: 2026-11-03
- 決めた人: Claude Code（推奨案で決めた。開発者が PR で確かめる）
- 関係する Issue と PR: #19
- 解決した未解決の項目: OQ-010
- 置き換える記録: なし

## 背景

`vision.md` の「やること」に、出題の範囲を観点シートの分類から選び、分類を複数選べ、どの分類からも出すランダムの出題もできる、とある。#17 では、分類を選ぶ画面ができるまで、すべての問題から出すことにしていた（[D-0007](D-0007-quiz-screen.md)）。

分類を選ぶ画面を作るにあたり、Issue #19 にある次のことを決める必要があった。開発者に直接尋ねられなかったので、`vision.md` の判断の基準と「やらないこと」に沿って推奨案を選び、[OQ-010](../open-questions.md#oq-010) に選択肢と推奨を書いたうえで、推奨案で決めた。

- 分類を選ぶ画面の URL と、トップページ、出題の画面とのつながり
- 選んだ分類を出題の画面にどう渡すか
- 分類の名前の日本語と英語での出し方
- 問題が1問もない分類を、選べるようにするか
- 出題の途中で分類を選び直す手段を置くか
- 選んだ分類を、次に開いたときにも残すか

## 決定

- 分類を選ぶ画面の URL は `/categories` にする。トップページの「問題を解く」は、出題の画面ではなく、分類を選ぶ画面を開く。
- 分類を選ぶ画面には、8つの分類のチェックボックスと、「選んだ分類で始める」のボタンと、「すべての分類から出す」のリンクを置く。分類を1つも選んでいないときは、「選んだ分類で始める」を押せない。
- 選んだ分類は、出題の画面の URL のクエリ `category` で渡す。分類を1つ選ぶごとに `category=<分類の id>` を1つ付ける。`category` がなければ、すべての分類から出す。分類の id でないものと重なったものは除き、何も残らなければすべての分類から出す。
- 出題の画面は、ビルドのときにすべての問題を読んで静的に作り、ブラウザーで `category` を読んで出す問題を絞る。
- 分類の名前は文言のファイルに置く。日本語は観点シートの節の名前にし、英語は、節に英語の名前が書いてあればそれを使い、なければ節の名前を英語にする。
- 問題が1問もない分類も選択肢に出すが、選べないようにする。
- 出題の画面に「分類を選び直す」のリンクを置く。リンクは、出題の画面と同じ `category` を付けて分類を選ぶ画面を開き、その分類を選んだ状態にする。
- 選んだ分類は保存しない。

詳しい振る舞いは [出題の範囲を分類から選ぶ画面](../specs/category-select.md) に書いた。

## ほかの選択肢

- トップページに分類の選択肢を置く案。トップページには設定画面へのリンクもあり、選択肢を置くと画面が込み入るので採らなかった。
- `/quiz` を開いたとき、`category` がなければ分類を選ぶ画面として出す案。`category` のない `/quiz` を「すべての分類から出す」に使えなくなるので採らなかった。
- 選んだ分類をローカルストレージに書き、出題の画面で読む案。URL だけでは出す問題が決まらなくなり、ブラウザーの「戻る」で前の範囲に戻れないので採らなかった。
- 分類ごとにページを作る案（`/quiz/numbers` など）。分類を複数選ぶと組み合わせが多く、すべてをビルドで作れないので採らなかった。
- 分類の名前を、言語によらず観点シートの節の名前で出す案。英語を選んだ人に日本語の名前が出るので採らなかった。
- 問題が1問もない分類を選択肢に出さない案。分類の並びが問題の有無で変わるので採らなかった。
- 問題が1問もない分類も選べるようにし、出題の画面で「問題がありません」と出す案。選んでから問題がないと分かるので採らなかった。
- 出題の画面に選び直す手段を置かず、トップページから選び直す案。スマートフォンでの操作が1回増えるので採らなかった。
- 選んだ分類をローカルストレージに保存し、次に開いたときに選んだ状態にする案。選んだ分類は学習の進め方に関わる記録に近く、`vision.md` の「やらないこと」の「学習の記録の保存」に当たるかどうかを、推奨案では決めきれない。保存しなくても出題はできるので採らなかった。

## 根拠

- URL のクエリで渡すと、ページはビルドのときに静的に作ったまま（[D-0003](D-0003-tech-stack.md)）、サーバーで処理せずに出す問題を決められる。問題は百数十問で、すべてをページに入れても重くない。
- URL だけで出す範囲が決まるので、ブラウザーの「戻る」と「進む」がそのまま使え、何も保存しない。
- チェックボックスとボタン1つは、スマートフォンでも押しやすく、画面もシンプルに保てる（`vision.md` の判断の基準）。
- 問題が1問もない分類を出したまま選べなくすると、分類の並びが観点シートの節と同じに保たれる。
