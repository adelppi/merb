# D-0020 分類を選ぶ画面から出題の画面へは、コンマ区切りのクエリで渡す

- 日付: 2026-11-03
- 決めた人: Claude Code（Issue #36 の指示に沿って決めた。adelppi が PR で確かめる）
- 関係する Issue と PR: #36
- 解決した未解決の項目: なし
- 置き換える記録: D-0008 のうち、選んだ分類を `category` のクエリに1つずつ付けて渡す点、出題の画面に「分類を選び直す」のリンクを置く点、ページをビルドのときに静的に作る点。分類の選択肢、押せない条件、問題のない分類を選べなくすること、選んだ分類を保存しないことは変えない

## 背景

[D-0012](D-0012-native-app.md) でアプリをネイティブにしたので、D-0008 の「ブラウザーの URL のクエリ」と「静的なページ」は前提でなくなった。[D-0018](D-0018-design-open-questions.md) で、出題の画面の戻るボタンは分類を選ぶ画面へ戻り、選んだ分類を選んだ状態にすると決めた。Expo Router の Stack で、分類を選ぶ画面から出題の画面へ移る方法を決め直す必要があった。

## 決定

- 分類を選ぶ画面のルートは `/categories` にする。ホームの「問題を解く」がここを開く。
- 「選んだ分類で始める」は、クエリ `categories` に分類の id をコンマで区切って付け、`/quiz?categories=numbers,fractions` のように開く。分類は分類の表の順に並べる。
- 「すべての分類から出す」は、クエリなしの `/quiz` を開く。クエリのない `/quiz` は、すべての分類から出す。
- 出題の画面は `categories` を読み、分類の id でないものと重なったものを除く。何も残らなければ、すべての分類から出す。
- 分類を選ぶ画面の選んだ状態は、その画面の state が持つ。出題の画面を開いても、Stack は分類を選ぶ画面を閉じないので、出題の画面の戻るボタン（`router.back()`）で戻ったときに選んだ状態が残る。URL では戻さず、端末にも保存しない。
- 出題の画面の「分類を選び直す」と「トップページへ戻る」のリンクはなくす（D-0018）。

## ほかの選択肢

- `category` を1つずつ繰り返す書き方（`?category=a&category=b`）。D-0008 の書き方。Expo Router のクエリは、同じ名前が重なると配列、1つだと文字列で返る。コンマ区切りの1つの文字列なら、受け取る側が型を分けずに読めるので採らなかった。
- 分類を選ぶ画面のクエリにも選んだ分類を付けて、戻ったときに URL から復元する案。Stack が画面を残すので要らず、画面の URL を書き換える手間が増えるので採らなかった。
- 選んだ分類を Context に持つ案。画面が2つで済む範囲では依存が増えるだけなので採らなかった。

## 根拠

- 出題の画面を直接開く経路（クエリなし）と、分類を選ぶ画面から開く経路が、同じクエリの読み方で足りる。
- 戻る動作は OS の標準の動き（Stack）に任せられ、戻ったときの復元を自分で書かずに済む。

## 影響

- `docs/specs/category-select.md` を、ネイティブアプリに合わせて書き換えた。
- `docs/specs/quiz.md` に残る `category` のクエリと2つのリンクの記述は、#35 で書き換える。
- `src/quiz/categories.ts` のクエリの名前と組み立てを、この決定に合わせる。
