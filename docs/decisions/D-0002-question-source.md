# D-0002 問題は事前に作って確かめ、リポジトリの JSON として持つ

- 日付: 2026-11-02
- 決めた人: adelppi
- 関係する Issue と PR: #1
- 解決した未解決の項目: OQ-003、OQ-004（問題の作り方に関わる部分）
- 置き換える記録: なし

## 背景

問題は、開発者が用意した観点シートをもとに LLM で作りたい。一方で、アプリには認証も DB も持たせない希望がある。LLM で作った問題を、いつ、どうやってアプリに渡すかを決める必要があった。

## 決定

- 問題は、観点シートをもとに LLM で事前に作る。開発者が中身を確かめてから、JSON としてリポジトリに入れる。
- アプリは、リポジトリに入れた JSON から出題する。
- サーバーで LLM を呼び、利用中に問題を作ることはしない。
- 利用者が自分で LLM に作らせた JSON を貼り付けて出題する機能は、今は作らない。必要になったら別の Issue で検討する。

## ほかの選択肢

- 利用中にサーバーで LLM を呼んで作る案。採らなかった。認証がないので誰でも API を呼べ、API キーの料金を他人に使われるおそれがある。1問ごとに待ち時間が出る。LLM が誤った読み方や描けない LaTeX を返しても、出題前に気づけない。
- プロンプトをコピーできるようにし、利用者が LLM に作らせた JSON を貼り付けて出題する案。料金はかからず誰でも問題を足せるが、問題の中身を誰も確かめない。スマートフォンで長い JSON を貼るのも手間になる。記録を保存しないので、再読み込みで問題が消える。まず事前に作る形を作り、この案は必要になったら足すことにした。

## 根拠

- 学習用のアプリでは、読み方が間違っていると利用者が間違いのほうを覚えてしまう。出す前に開発者が確かめられる形にした。
- 認証なし、DB なしの希望と合い、アプリに LLM の API キーを置かなくてよい。

## 影響
