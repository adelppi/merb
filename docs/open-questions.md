# 未解決の項目

まだ決まっていない要件や疑問を書きためる。ドキュメントやコードを書いている途中で決められないことが出たら、その場で追記する。

## 書き方

- 番号は `OQ-` に3桁の連番を付ける。一度付けた番号は使い回さない。
- 新しい項目は「未解決」の節の末尾に足す。
- 解決したら、項目を「解決済み」の節へ移し、状態を「解決」にして、決定（`decisions/`）へのリンクを書く。
- 決めないことにした項目は、状態を「取り下げ」にして理由を1行書き、「解決済み」の節へ移す。
- 項目は消さない。

項目の形は次のとおり。

```markdown
### OQ-000

- 問い: （何が決まっていないか）
- 状態: 未解決 / 解決 / 取り下げ
- 起票: YYYY-MM-DD、Issue #番号（あれば）
- 影響: （決まらないと進められないもの。仕様のファイルや Issue）
- 選択肢: （分かっていれば）
- 決定: （解決したら decisions/ へのリンク）
```

### OQ-010

- 問い: 出題の範囲を分類から選ぶ画面をどう作るか。画面の URL とトップページ・出題の画面とのつながり、選んだ分類を出題の画面に渡す方法、分類の名前の日本語と英語での出し方、問題が1問もない分類を選べるようにするか、出題の途中で分類を選び直す手段を置くか、選んだ分類を次に開いたときにも残すか。
- 状態: 解決
- 起票: 2026-11-03、Issue #19
- 影響: `docs/specs/category-select.md`、`docs/specs/quiz.md` の「出す問題」
- 選択肢:
  - 画面の URL: (a) `/categories` に分類を選ぶ画面を作り、トップページの「問題を解く」から開く（推奨）。(b) トップページに分類の選択肢を置く。(c) `/quiz` を、`category` がなければ分類を選ぶ画面として出す。
  - 渡し方: (a) URL のクエリ `category` を分類ごとに付ける（推奨）。(b) ローカルストレージに書き、出題の画面で読む。(c) 分類ごとにページを作る（`/quiz/numbers` など）。
  - 分類の名前: (a) 文言のファイルに分類の名前を置き、日本語は観点シートの節の名前、英語は節に英語の名前があればそれを使う（推奨）。(b) 言語によらず、観点シートの節の名前で出す。
  - 問題がない分類: (a) 選択肢に出すが、選べないようにする（推奨）。(b) 選択肢に出さない。(c) 選べるようにし、出題の画面で「問題がありません」と出す。
  - 選び直す手段: (a) 出題の画面に、いま選んでいる分類を選んだ状態で分類を選ぶ画面を開くリンクを置く（推奨）。(b) 置かず、トップページから選び直す。
  - 次に開いたとき: (a) 残さない（推奨）。(b) ローカルストレージに保存し、次に開いたときに選んだ状態にする。
- 決定: [D-0008](decisions/D-0008-category-select.md)
