# 問題の JSON の形

- 状態: 実装済み
- Issue: #6、#11
- 関係する決定: [D-0001](../decisions/D-0001-vision.md)、[D-0002](../decisions/D-0002-question-source.md)、[D-0003](../decisions/D-0003-tech-stack.md)、[D-0004](../decisions/D-0004-question-format.md)

## 目的

`vision.md` の「やること」にある並び替えの問題を、リポジトリの JSON として持つための形を決める。問題は観点シートをもとに LLM で作り、開発者が中身を確かめてからリポジトリに入れる（[D-0002](../decisions/D-0002-question-source.md)）。アプリはこの形の JSON から出題する。

## ファイルの置き場

| ファイル | 中身 |
|---|---|
| `content/perspectives.md` | 観点シート |
| `content/prompt.md` | 問題を作るためのプロンプト |
| `content/questions/<分類の id>.json` | 問題。分類ごとに1つのファイルにする |

## 分類

出題の範囲で選ぶ分類は、観点シートの節の8つにする。分類の id は次のとおり。

| 分類の id | 観点シートの節 |
|---|---|
| `numbers` | 1. 数（numbers） |
| `fractions` | 2. 分数（fractions） |
| `scripts-powers-roots` | 3. 添え字・累乗・根号（suffixes, powers, roots） |
| `arithmetic` | 4. 四則演算・括弧 |
| `vectors-functions` | 5. ベクトル・行列・関数 |
| `calculus` | 6. 微分・積分・総和 |
| `relations` | 7. 等式・不等式・関係記号 |
| `combined` | 8. まとまった数式 |

## ファイルの形

1つのファイルは、次の形の JSON にする。

```json
{
  "category": "scripts-powers-roots",
  "questions": [
    {
      "id": "scripts-powers-roots-001",
      "perspective": "n乗（序数＋power）",
      "latex": "x^5",
      "answers": [
        { "cards": ["x", "to", "the", "fifth", "power"] },
        { "cards": ["x", "to", "the", "fifth"] }
      ],
      "distractors": ["five"]
    }
  ]
}
```

| キー | 型 | 必須 | 中身 |
|---|---|---|---|
| `category` | 文字列 | 必須 | 分類の id。ファイル名の `<分類の id>` と同じにする |
| `questions` | 配列 | 必須 | 問題の配列。1問以上 |

問題の1つは、次のキーを持つ。

| キー | 型 | 必須 | 中身 |
|---|---|---|---|
| `id` | 文字列 | 必須 | 問題の id。`<分類の id>-<3桁の連番>` の形にする。すべてのファイルを通して重ならない |
| `perspective` | 文字列 | 必須 | もとにした観点。節 1〜7 では観点シートの表の「観点」の欄、節 8 では「式」の欄の式の名前（例: `解の公式`）を、そのまま写す |
| `latex` | 文字列 | 必須 | 画面に描く数式。KaTeX で描ける LaTeX にする。`$` で囲まない |
| `answers` | 配列 | 必須 | 正解の配列。1つ以上 |
| `distractors` | 文字列の配列 | 必須 | まぎらわしい札。なければ空の配列にする |

正解の1つは、次のキーを持つ。

| キー | 型 | 必須 | 中身 |
|---|---|---|---|
| `cards` | 文字列の配列 | 必須 | 正解の読み方を、回答エリアに並べる順に札で書いたもの。1枚以上 |
| `text` | 文字列 | 任意 | 答えを見せるときの読み方。カンマを入れたいときに書く。書かないときは、`cards` を半角スペース1つでつないだものを見せる |

`text` からカンマを除き、空白を半角スペース1つにそろえたものは、`cards` を半角スペース1つでつないだものと同じにする。

## 札

- 札は単語で区切るのを基本とする。長い式では、意味のまとまり（例: `the square root of`）を1枚の札にしてよい。
- 札には句読点（`,` `.` `;` `:` `!` `?`）を入れない。
- 札の文字列は空にしない。前後に空白を入れず、単語の間の空白は半角スペース1つにする。
- 大文字と小文字は、数式の文字に合わせて書き分ける（例: `F of omega` の `F` と、`f of t` の `f`）。

## 出す札

1つの問題で出す札は、次の2つを合わせたもの。

- 正解の札: 同じ文字列の札は、`answers` のうち、その文字列をいちばん多く使う正解の枚数だけ出す。こうして、どの正解も組み立てられるようにする。
- まぎらわしい札: `distractors` の札をすべて出す。

ある正解で使わない札は、その正解を組み立てたときに余る。`distractors` には、`answers` の札と同じ文字列を入れない。

## 判定

1. 回答エリアに並んだ札の文字列を、並んだ順に取り出す。
2. その列が、`answers` のどれか1つの `cards` と、長さも順番も同じで、各札の文字列が完全に一致すれば正解とする。大文字と小文字は区別する。
3. 同じ文字列の札は、どれを使っても同じに扱う。
4. 余った札があっても、正解かどうかには関わらない。

## 検査

受け入れ条件は、`pnpm test` で実行する Vitest のテストで確かめる。テストは `content/questions/` のすべての JSON を読む。JSON が1つもないときも、テストは通る。

「KaTeX で描ける」は、KaTeX の `renderToString` に `throwOnError: true` と `strict: "error"` を渡して、エラーにならないことをいう。

## 受け入れ条件

この条件をすべて満たせば実装済みとする。テストはこの条件と対応させる（[D-0003](../decisions/D-0003-tech-stack.md)）。

- [x] `content/questions/` のすべての JSON が、この仕様の形に合っている。
- [x] `category` が、分類の id のどれかで、ファイル名と同じになっている。
- [x] 問題の `id` が、形に合っていて、すべてのファイルを通して重ならない。
- [x] `perspective` が、観点シートにある観点か式の名前と一致する。
- [x] すべての `latex` を KaTeX で描ける。
- [x] 札が「札」の節の決まりに合っている。
- [x] `distractors` に、`answers` の札と同じ文字列がない。
- [x] `text` が、同じ正解の `cards` と食い違っていない。
- [x] 「出す札」の決まりで出した札から、すべての正解を組み立てられる。
- [x] 判定が「判定」の節のとおりに動く。

## 範囲外

この仕様で扱わないこと。

- 問題そのものを作ること
- 出題の画面と、札を並べる操作
