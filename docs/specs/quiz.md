# 1問を解く出題の画面

- 状態: 合意
- Issue: #17、#19、#22、#23、#24、#35
- 関係する決定: [D-0004](../decisions/D-0004-question-format.md)、[D-0007](../decisions/D-0007-quiz-screen.md)、[D-0009](../decisions/D-0009-card-font.md)、[D-0010](../decisions/D-0010-retry-without-button.md)、[D-0011](../decisions/D-0011-question-prompt.md)、[D-0012](../decisions/D-0012-native-app.md)、[D-0014](../decisions/D-0014-ios-expo-router.md)、[D-0016](../decisions/D-0016-math-and-drag-libs.md)、[D-0018](../decisions/D-0018-design-open-questions.md)、[D-0019](../decisions/D-0019-i18n-and-locale-storage.md)、[D-0020](../decisions/D-0020-category-navigation.md)、[D-0021](../decisions/D-0021-operation-test-tool.md)
- デザイン: [docs/design/](../design/README.md) の出題の4つの状態（2a 解答中、2b 不正解、2c 正解、2d 答えを見た後）

## 目的

`vision.md` の「やること」にある、数式の英語での読み方を問う並び替えの問題を出す。利用者は、数式を見て札を並べ、答え合わせをする。間違えたときは、ボタンを押さずにそのまま札を並べ直して解き直すか、答えを見るかを選べる。

## 出す問題

1. 問題は、アプリに同梱した `content/questions/` の JSON から読む。読み込みのとき、[問題の JSON の形](question-format.md)の Zod の形にかける。形に合わない JSON があれば、例外を投げる。
2. 出す問題は、クエリ `categories` で選んだ分類の問題にする。決まりは[分類を選ぶ画面](category-select.md#出題の画面で出す問題)に書いた。
3. クエリ `question` に問題の `id` があり、出す問題の中にその問題があれば、最初の1問をその問題にする。確かめ用で、画面からは付けない。ない、または出す問題の中にないときは、最初の1問もランダムに選ぶ。
4. 次の問題は、出す問題の中からランダムに選ぶ。出す問題が2問以上あるときは、直前と同じ問題を選ばない。
5. 出す問題が1問もないときは、画面の中央に「問題がありません」と出す。ほかの部品は置かない。

## 画面

画面の移動は Expo Router の Stack で行い、出題の画面のルートは `/quiz` にする。[分類を選ぶ画面](category-select.md)から開く。

1. 左上に戻るボタンを置く。戻るボタンは Stack のヘッダーで出し、大見出しは置かない。押すと、分類を選ぶ画面へ戻り、選んでいた分類を選んだ状態で出す（[D-0018](../decisions/D-0018-design-open-questions.md)、[D-0020](../decisions/D-0020-category-navigation.md)）。スワイプは無効にし、画面の端からのスワイプでは戻らない。戻るときは戻るボタンを使う。「分類を選び直す」と「トップページへ戻る」のリンクは置かない。
2. 画面には、上から順に、問題文、数式、回答エリア、札置き場を置く。回答エリアと札置き場のあいだに、状態の表示（「正解」「不正解」と読み方）を出す。ボタンは画面の下に固定する。内容が長いときは、本体をスクロールできるようにし、下のボタンに隠れないようにする。
3. 問題文は、問題の JSON の `prompt` のうち、選んでいる言語のほうを、薄い文字色の小さな文字（15pt）で出す（[問題の JSON の形](question-format.md)の「問題文」の節）。日本語を選んでいれば `ja` を、英語を選んでいれば `en` を出す。
4. 数式は KaTeX で描き、中央に大きく出す（[D-0016](../decisions/D-0016-math-and-drag-libs.md)）。設定は、問題の JSON の検査と同じにする（[問題の JSON の形](question-format.md)の「検査」の節）。
5. 回答エリアは、薄い藍の角丸（22）の枠で、最小の高さを 116 にする。札は左上から並べ、折り返す。札の間隔は 8、枠の内側の余白は 12 にする。
6. 札置き場には、[出す札](question-format.md#出す札)の決まりで出した札を、混ぜて並べる。問題を出すたびに混ぜ直す。枠は付けない。札が1枚もなくても、札を戻せるだけの高さを残す。
7. 札は、高さ 44、角丸 12、左右の余白 16 にする。札置き場の札は白い背景に薄い影、回答エリアの札は藍の背景に白い文字にする。正解のときだけ、回答エリアの札を緑の背景にする。不正解のときも、回答エリアの札は藍のままで、位置ごとに緑と赤で分けない（[D-0018](../decisions/D-0018-design-open-questions.md)）。
8. 札の文字は、数式と同じ KaTeX の書体で出す。回答エリア、札置き場、ドラッグ中の札で同じ書体にする。
   - 札の文字列が英字1文字（`A`〜`Z`、`a`〜`z`）のときは、数式の中の文字と同じ斜体で出す。英単語の `a`（`a half` の `a` など）も、英字1文字なので斜体で出す。
   - ほかの札は、KaTeX の立体で出す。
   - 書体を変えても、判定と札の読み上げ用の名前は、札の文字列のままにする。
9. 答えを見せるときの読み方（「ほかの読み方」と「答え」）は、札の書体にせず、画面の文言と同じ書体で出す。読み上げの言語は英語にする。
10. 下のボタンは、「答え合わせ」と「次の問題」を藍の目立つボタンに、「答えを見る」を控えめなボタンにする。控えめなボタンは、iOS 26 以上では Liquid Glass、それより前の iOS では半透明の背景で出す（[D-0018](../decisions/D-0018-design-open-questions.md)）。アイコンを使うときは SF Symbols にする。
11. 背景の色と、藍、緑、赤の色は、デザインの値にそろえる（`src/components/theme.ts`）。

## 札を運ぶ

答え合わせをする前と、間違えたあとは、次の操作で札を運べる。

1. 札置き場の札をタップすると、その札を回答エリアの末尾へ運ぶ。
2. 回答エリアの札をタップすると、その札を札置き場の元の位置へ戻す。札置き場の札の並びは、問題を出したときから変わらない。
3. 札置き場の札を長押ししてドラッグし、回答エリアに落とすと、その位置へ入れる。回答エリアの札の上に落とすとその札の前に、札のないところに落とすと末尾に入れる。
4. 回答エリアの札を長押ししてドラッグすると、回答エリアの中で並べ替えられる。札の上に落とすとその札の位置へ、札のないところに落とすと末尾へ移す。
5. 回答エリアの札をドラッグして札置き場に落とすと、札置き場の元の位置へ戻す。
6. 札置き場の中では並べ替えない。札置き場の札を札置き場に落としても、何も変わらない。回答エリアにも札置き場にも落とさなかったときも、何も変わらない。
7. 約 0.25 秒（250 ミリ秒）押し続けたときにドラッグを始める。それより短い操作はタップとして扱う（[D-0016](../decisions/D-0016-math-and-drag-libs.md)）。
8. 札は、VoiceOver でボタンとして読み上げる。ダブルタップは、タップと同じに運ぶ。ドラッグだけでしかできない運び方はない。

## 答え合わせ

1. 答え合わせは、「答え合わせ」のボタンを押したときにする。回答エリアに札が1枚もなくても押せる。
2. 判定は、[問題の JSON の形](question-format.md)の「判定」の節のとおりにする。札が1枚もなければ不正解にする。
3. 正解したあとと、答えを見たあとは、次の問題を出すまで札を運べない。このとき札置き場は出さない。

### 解いているとき（2a）

1. 回答エリアと札置き場を出す。
2. 下に「答え合わせ」のボタンを出す。

### 正解したとき（2c）

1. 「正解」と、緑のチェックの印を出す。回答エリアの札は緑にする。
2. 札置き場を出さない。
3. 読み方が複数ある問題では、回答エリアに並べたもの以外の読み方を、「ほかの読み方」として `answers` の順に見せる。
4. 「次の問題」のボタンを出す。押すと次の問題を出す。

### 間違えたとき（2b）

1. 「不正解」と、赤の印を出す。回答エリアの札は、並べたまま、藍で見せる。札置き場も出す。
2. 「答えを見る」と「答え合わせ」のボタンを出す。「次の問題」のボタンは出さない。
3. ボタンを押さずに、そのまま札を運べる（「札を運ぶ」の節）。札を運んで回答エリアの並びが変わったら、「不正解」の表示を消す。「答えを見る」のボタンは、次の問題を出すまで出したままにする。
4. 札を並べ直してから、または並べ直さずに、もう一度「答え合わせ」を押せる。判定は「答え合わせ」の節の1と2のとおりにし、正解なら「正解したとき」のとおりにする。
5. 続けて不正解になったときも、答え合わせのたびに「不正解」を出し直す。出し直すときは、「不正解」を 0.3 秒ほど左右に小さく揺らす。iOS の「視差効果を減らす」（動きを減らす設定）を有効にしているときは、揺らさずに、0.3 秒ほどかけて薄い色から元の色に戻して出す。
6. 間違えた回数は数えず、見せない。
7. 「答えを見る」を押すと、「答えを見たとき」のとおりにする。

### 答えを見たとき（2d）

1. 「答え」として、すべての読み方を `answers` の順に、区切り線で分けて見せる。
2. 「不正解」の表示と札置き場は出さない。回答エリアの札は藍のまま、運べない。
3. 「次の問題」のボタンを出す。

### 読み方の見せ方

読み方は、正解の `text` があれば `text` を、なければ `cards` を半角スペース1つでつないだものを見せる。

## 文言

画面の文言は、`src/i18n/messages/ja.json` と `en.json` から `useI18n()` で読んで出す（[画面の文言の言語の切り替え](i18n.md)）。数式と札と読み方は、言語によらず問題の JSON のまま出す。問題文は、「画面」の節のとおり、選んでいる言語のものを問題の JSON から出す。

## 受け入れ条件

この条件をすべて満たせば実装済みとする。テストはこの条件と対応させる。道具は [D-0021](../decisions/D-0021-operation-test-tool.md) のとおり、判断を持つ処理は Vitest、画面の操作は Maestro（`maestro/`）で確かめる。

- [x] `/quiz` を開くと、問題文、数式、混ぜた札、「答え合わせ」のボタンが出る（Maestro: `correct`）
- [x] 札置き場の札をタップすると回答エリアの末尾へ、回答エリアの札をタップすると札置き場の元の位置へ動く（Vitest: reducer。Maestro: `incorrect`）
- [ ] 札置き場の札と回答エリアの札を、長押ししてのドラッグで運べる（Vitest: `resolveDrop`。画面のドラッグは確かめられていない。下の注記を参照）
- [x] 回答エリアの中での並べ替えと、札置き場へ戻す動きが「札を運ぶ」の節のとおりになる（Vitest: reducer と `resolveDrop`）
- [x] 札を並べて答え合わせをすると、正解なら「正解」と、ほかの読み方と、「次の問題」が出て、札置き場は出ない（Vitest: `quizView`。Maestro: `correct`）
- [x] 間違えて答え合わせをすると、「不正解」と、「答え合わせ」と「答えを見る」のボタンが出て、「次の問題」のボタンは出ない（Vitest: `quizView`。Maestro: `incorrect`）
- [x] 間違えたあと、ボタンを押さずに札を運び、もう一度答え合わせができる（Vitest: reducer。Maestro: `incorrect`）
- [x] 間違えたあとに札を運んで並びが変わると、「不正解」の表示が消え、「答えを見る」のボタンは残る（Vitest: `quizView`。Maestro: `incorrect`）
- [x] 続けて不正解になると、答え合わせのたびに「不正解」を出し直す（Vitest: reducer の答え合わせの回数。Maestro: `incorrect`。揺れの動きは目で確かめる）
- [x] 「答えを見る」で、すべての読み方が出て、「不正解」と札置き場は出ない（Vitest: `quizView`。Maestro: `reveal`）
- [x] 札が1枚もなくても答え合わせができ、不正解になる（Vitest。Maestro: `incorrect`）
- [x] 正解したあとと、答えを見たあとは、次の問題を出すまで札を運べない（Vitest）
- [x] 札を混ぜる処理は、渡した乱数で結果が決まり、札をなくしたり増やしたりしない（Vitest）
- [x] 次の問題を選ぶ処理は、問題が2問以上あれば直前と同じ問題を選ばない。`question` の問題を最初に出せる（Vitest）
- [x] 問題が1問もないときは「問題がありません」と出す（`src/app/quiz.tsx`。画面で確かめていない）
- [x] 出題の画面の戻るボタンで分類を選ぶ画面へ戻り、選んだ分類が残っている（Maestro: `back`）
- [ ] 英語を選んでいるときは、出題の画面の文言が英語で出る（文言のファイルが同じキーを持つことは Vitest。画面は確かめていない）
- [ ] 数式の上に、選んでいる言語の問題文が出る（日本語は Maestro の画面で確かめた。英語は確かめていない）
- [x] 英字1文字の札は KaTeX の斜体で、ほかの札は KaTeX の立体で出る。札の読み上げ用の名前は札の文字列のままになる（Maestro は札の文字列で札を押している。書体は目で確かめた）

注記: 画面の札のドラッグは、Maestro では送れない。Maestro の `swipe` は押したまま待たずに動かし始めるので、250 ミリ秒の長押しが済む前に動き出し、ドラッグが始まらない。落とす位置から運び先を決める処理は Vitest で確かめたが、画面で札が指に付いて動き、落とした位置に入ることは、確かめられていない。

## 範囲外

この仕様で扱わないこと。

- 分類を選ぶ画面（[出題の範囲を分類から選ぶ画面](category-select.md)）
- 問題の JSON の中身を作ること
- 解いた問題の数や正解の数を数えること（`vision.md` の「やらないこと」の「進捗の管理」と「ゲーム性」）
- ダークモード（デザインに画面がない）
